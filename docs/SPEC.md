# td3d — спецификация MVP

- **Статус:** draft, до начала реализации
- **Версия:** 0.2 (2026-10-09) — по итогам grill: реестр врагов, волны с паузой, старт/победа/поражение, процедурные анимации, снят лимит в 12 часов; этап 7.10 «Релиз»
- **Репозиторий:** https://github.com/msilkov/td3d
- **Словарь:** [GLOSSARY.md](../GLOSSARY.md) · **Решения:** [docs/adr/](adr/)

Документ — источник истины по MVP. Реализация идёт строго по нему; отклонение —
повод сначала обновить спеку, потом писать код. По ходу работы спека правится по факту,
чтобы на выходе получилась готовая документация, а не археология по коммитам.
Термины — из глоссария.

## 1. Цель

Играбельный 3D tower defense в браузере: волны врагов идут по фиксированному пути к базе,
игрок строит башни в слотах за деньги, башни сами стреляют по врагам.
Победа — пережить все волны, поражение — потерять все жизни.

**Граница MVP — первая играбельная версия по ссылке** ([ADR 0003](adr/0003-mvp-without-time-budget.md)).
Лимита по времени нет; всё, что не нужно для играбельности и обкатки ключевых подсистем,
делается итерациями после MVP.

**Вторая цель:** обкатать R3F перед большим проектом ([ADR 0001](adr/0001-web-stack-r3f.md)).
Поэтому важнее, чтобы подсистемы получились переиспользуемыми, чем чтобы игра была глубокой.
По той же причине в MVP входят дешёвые процедурные анимации — их всё равно придётся уметь делать.

## 2. Scope

### В MVP входит

- Один уровень с фиксированным путём
- Один тип врага, один тип башни, один режим наведения (ближайший к башне враг)
- Партия: «Старт» из ожидания, волны с паузой после зачистки, победа/поражение, рестарт
- Постройка башен в слоты за деньги, предпросмотр радиуса при наведении
- Экономика: награда за убийство, стоимость башни
- Процедурные анимации: покачивание врагов, поворот башни к цели, линия выстрела,
  финальные сцены победы и поражения
- Модели из CC0-пака вместо примитивов
- Деплой на Vercel

### Не входит — сознательно

Всё это — итерации после первой ссылки (§9):

апгрейды и продажа башен · несколько типов врагов и башен · ручной выбор режима наведения ·
скелетная анимация моделей · звук и музыка · главное меню и настройки · сохранения ·
несколько уровней · партиклы и постобработка · мобильное управление · управление камерой · бэкенд.

### Технические упрощения и их цена

| Упрощение | Вместо чего | Что экономит |
|---|---|---|
| Слоты под башни | свободное размещение | raycast в плоскость земли, снап к сетке, валидация места |
| Hitscan-урон | летящие снаряды | баллистика, упреждение, пул снарядов, коллизии |
| Фиксированная кривая пути | pathfinding | A\*, navmesh, перестроение маршрута при застройке |
| Процедурные анимации | скелетные | риггинг, анимированные модели, `useAnimations`, блендинг клипов |

Ни одно из них не мешает игре быть игрой. Все обратимы, если проект пойдёт дальше.

## 3. Стек

```
Vite + React 19 + TypeScript
three.js + @react-three/fiber + @react-three/drei
zustand
Vitest — только для логики (§8)
```

Каркас уже стоит (PR #1). Vitest ставится вместе с первой логикой.

Арт: **Kenney Tower Defense Kit** (CC0). Кладём `.glb` в `public/models/`,
грузим через `useGLTF` из drei. Если в паке только `.obj` — вторым источником Quaternius.

## 4. Архитектура состояния

Центральное решение, от которого зависит производительность ([ADR 0002](adr/0002-enemy-registry-outside-react.md)).

**Три места, разделённые по частоте изменений и по тому, кто читает:**

| | Где живёт | Что там | Кто пишет / читает |
|---|---|---|---|
| Реестр врагов | модульный `Map` вне React и zustand | прогресс, позиция, здоровье, награда каждого врага | `<Enemy>` пишет в `useFrame`, `<Tower>` читает в `useFrame` |
| Локальное покадровое | `useRef` в компоненте | перезарядка башни, таймер линии выстрела, фаза анимации | только сам компонент |
| Событийное | zustand | деньги, жизни, номер волны, статус, id живых врагов, башни | UI и рендер списков |

**Правило:** ничего, что меняется каждый кадр, не попадает в React state. Позиции врагов
в `useState` = ререндер дерева 60 раз в секунду и мгновенная просадка FPS.

**Реестр и стор меняются вместе только через функции реестра** — `spawnEnemy`, `killEnemy`,
`leakEnemy`. Каждая за один вызов меняет и `Map`, и стор, поэтому рассинхрон
«в реестре есть, в сторе нет» невозможен по построению. Компоненты не трогают ни `Map`,
ни список id напрямую.

**Убийство засчитывается ровно один раз.** `useFrame` выполняется синхронно и по очереди,
гонки нет: убийство засчитывает башня, после чьего попадания здоровье ≤ 0; вторая башня
в том же кадре врага в реестре уже не находит и не стреляет. `killEnemy` дополнительно
идемпотентен — для отсутствующего id это no-op.

**После победы или поражения сцена замирает:** каждый игровой `useFrame` выходит сразу,
если статус не `playing`. Иначе оставшиеся враги продолжают утекать (жизни в минус),
а башни — приносить деньги. Исключение — финальные сцены (§6), они анимируются как раз в `won`/`lost`.

Если на 30+ врагах просядет FPS — оптимизация следующего уровня: пул из N фиксированных
мешей с `visible={false}` для неактивных. В MVP не делаем заранее.

## 5. Модель данных

### Конфиг уровня — статика

```ts
type Vec3 = [number, number, number]

type WaveConfig = {
  count: number      // врагов в волне
  interval: number   // секунд между спавнами
  enemyHp: number
  enemySpeed: number // мировых единиц в секунду
  reward: number     // денег за убийство
}

type TowerType = {
  id: string
  cost: number
  range: number      // радиус в мировых единицах
  damage: number
  cooldown: number   // секунд между выстрелами
}

type LevelConfig = {
  path: Vec3[]         // контрольные точки кривой, ~8 штук
  slots: Vec3[]        // позиции слотов под башни
  waves: WaveConfig[]
  wavePause: number    // секунд от зачистки волны до первого спавна следующей
  startMoney: number
  startLives: number
}
```

**Скорость и прогресс.** `enemySpeed` — в мировых единицах в секунду, чтобы её можно было
сравнивать с `range` и она не меняла смысл при удлинении пути. На каждом кадре
`t += enemySpeed * delta / curveLength`, позиция — `curve.getPointAt(t)` (параметризация
по длине дуги, без рывков на изгибах). Длина кривой считается один раз.

### Реестр врагов

```ts
type EnemyState = {
  id: number
  t: number          // прогресс 0..1
  position: Vector3  // пишется в useFrame врага, читается башнями
  hp: number         // копируется из WaveConfig при спавне
  speed: number      // копируется из WaveConfig при спавне
  reward: number     // копируется из WaveConfig при спавне
}
```

Функции реестра: `spawnEnemy(wave)`, `damageEnemy(id, amount)` (при hp ≤ 0 → `killEnemy`),
`killEnemy(id)` (удалить, `money += reward`, идемпотентно), `leakEnemy(id)` (удалить,
`lives--`, при 0 → `lost`), `clearEnemies()` (для рестарта).

### Стор (zustand)

```ts
type PlacedTower = { slotIndex: number; typeId: string }

type GameStore = {
  money: number
  lives: number
  waveIndex: number
  status: 'idle' | 'playing' | 'won' | 'lost'
  enemyIds: number[]
  towers: PlacedTower[]

  startGame(): void                                  // idle → playing
  buildTower(slotIndex: number, typeId: string): void // только idle/playing, хватает денег, слот свободен
  reset(): void                                      // значения из LevelConfig, статус idle
}
```

`hp` и `t` в сторе нет — они в реестре.

### Партия

- **Ожидание (`idle`)** — после загрузки и после рестарта. Волны не идут, строить можно.
- **«Старт»** в HUD переводит в `playing`.
- **Волны.** Враги волны появляются по одному через `interval`. После **зачистки волны**
  (все её враги убиты или утекли) — пауза `wavePause`, затем следующая. Волны не наслаиваются.
- **Поражение** — сразу, как только жизни дошли до 0; оставшихся врагов не ждём.
- **Победа** — последняя волна заспавнена целиком, живых врагов нет, жизней больше 0.
- Если оба условия наступили одновременно (последний враг утёк и забрал последнюю жизнь) — **поражение**.
- **Строить** можно в `idle` и `playing`, включая во время волны; в `won`/`lost` нельзя.
- **Рестарт** с экрана победы или поражения: `clearEnemies()`, `reset()`, таймеры волн
  останавливаются сами, потому что тикают только в `playing`.

Логика волн — чистая функция `tickWaves(state, delta, level)`, которая возвращает новое
состояние волн и сколько врагов заспавнить. Хук `useWaves` — тонкая обёртка над `useFrame`.

### Бой

- **Выбор цели** — чистая функция `pickTarget(towerPosition, range, enemies, mode)`.
  В MVP один режим `'nearest'` — ближайший к башне враг в радиусе. Новый режим потом
  добавляется веткой в функции и кнопкой в UI, без переписывания `<Tower>`.
- **Перезарядка** отсчитывается всегда, даже без цели. Только что построенная башня
  готова стрелять сразу. Выстрел — когда башня готова и цель есть.

## 6. Структура компонентов

```
src/
  game/
    config/level1.ts     LevelConfig
    store.ts             zustand
    enemies.ts           реестр врагов + spawn/damage/kill/leak/clear
    targeting.ts         pickTarget
    waves.ts             tickWaves
    curve.ts             CatmullRomCurve3 из path, длина, getPointAt
    useWaves.ts          useFrame-обёртка над tickWaves
  components/
    Scene.tsx            Canvas, ортокамера вдоль оси карты с наклоном, свет
    Ground.tsx           игровое поле, фон за его краем, визуализация дороги
    Enemy.tsx            один враг: движение по кривой и покачивание в useFrame
    Enemies.tsx          маппинг store.enemyIds → <Enemy>
    Slot.tsx             кликабельный слот, предпросмотр радиуса при наведении
    Tower.tsx            выбор цели, поворот к ней, урон по перезарядке, линия выстрела
    EndScene.tsx         финальная сцена победы/поражения в 3D
    HUD.tsx              HTML-оверлей: деньги, жизни, волна, кнопка «Старт»
    EndScreen.tsx        Win/Lose + рестарт
  App.tsx
```

HUD и EndScreen — обычный HTML поверх `<Canvas>`, не `<Html>` из drei.

**Камера.** `OrthographicCamera` смотрит вдоль оси Z карты с наклоном ~55° от горизонта, без поворота
по диагонали — поле читается прямоугольником, а не ромбом. Игровое поле прямоугольное, 16:9.
Зум подбирается по размеру окна так, чтобы поле влезало целиком; остаток кадра закрывает фон —
плоскость заметно больше поля, поэтому чёрных полей нет ни на каком соотношении сторон.
Камера неподвижна: панорамы и зума мышью в MVP нет.

**Анимации — процедурные** (трансформы и цвет в `useFrame`, без скелета):

| Что | Как |
|---|---|
| Враг идёт | покачивание по Y и лёгкий наклон с фазой от id |
| Башня целится | плавный поворот по Y к цели |
| Выстрел | линия от башни к цели, видна ~100 мс |
| Победа | камера медленно облетает карту, башни коротко подпрыгивают |
| Поражение | сцена плавно уходит в серый/красный тон, вспышка света на базе |

**Предпросмотр радиуса:** при наведении на пустой слот — полупрозрачное кольцо радиуса
будущей башни; при наведении на построенную — её собственный радиус.

## 7. Этапы и критерии приёмки

Порядок не переставлять: 7.1–7.3 дают «что-то живое двигается по экрану» — главный
источник мотивации. Модели и анимации стоят последними сознательно: игра важнее красоты.

| # | Этап | Критерий приёмки |
|---|---|---|
| 7.1 | Сцена: `<Canvas>`, `OrthographicCamera` вдоль оси карты с наклоном, поле 16:9, фон, свет | Карта видна целиком, за её краем фон, а не пустота; сцена рендерится без ошибок в консоли |
| 7.2 | Кривая пути, реестр врагов, куб едет от старта до базы | Куб доезжает до конца за `длина пути / enemySpeed` секунд, утечка уменьшает `lives` на 1 |
| 7.3 | Волны: «Старт», спавн с интервалом, пауза после зачистки | Три волны подряд отрабатывают без вмешательства; следующая не начинается до зачистки предыдущей |
| 7.4 | Башня: радиус, `pickTarget('nearest')`, урон по перезарядке | Башня из хардкод-координат убивает врагов; награда начисляется ровно один раз при двух башнях на цели; на 30 врагах FPS не проседает |
| 7.5 | Слоты, постройка по клику, предпросмотр радиуса | Строятся 2–3 башни, деньги списываются и начисляются, в занятый слот и без денег построить нельзя, радиус виден до постройки |
| 7.6 | HUD, победа/поражение, замирание сцены, рестарт | Полный цикл поражения и перезапуска без перезагрузки страницы; после финала враги не двигаются, жизни не уходят в минус |
| 7.7 | Баланс: HP, урон, цены, состав волн, `wavePause` | Проигрывается при бездействии; выигрывается при разумной игре; не выигрывается автоматически |
| 7.8 | Модели Kenney вместо примитивов | Выглядит как игра, а не как прототип |
| 7.9 | Процедурные анимации | Враги покачиваются, башни поворачиваются к цели, выстрел виден, у победы и поражения своя финальная сцена |
| 7.10 | Релиз: деплой на Vercel, README со скриншотом и видео, тег `v0.1.0` | Выполнен DoD (§9): играется по ссылке в чужом браузере, в README скриншот и запись 30–60 секунд, тег `v0.1.0` с release notes |

## 8. Тестирование

**Один шов — публичный API игровой логики** (`src/game/`): действия стора, функции реестра,
`pickTarget`, `tickWaves`. Тесты на Vitest вызывают эти функции и проверяют наблюдаемый
результат — деньги, жизни, статус, список id, выбранную цель, сколько врагов заспавнить.
Внутреннее устройство (`Map`, поля стора, не видимые снаружи) тесты не трогают.

Что покрываем:

- **Стор:** `startGame` только из `idle`; `buildTower` отказывает при нехватке денег, занятом
  слоте и в `won`/`lost`; `reset` возвращает значения уровня.
- **Реестр:** награда начисляется один раз при повторном `killEnemy`; утечка уменьшает жизни
  и при 0 даёт `lost`; поражение важнее победы при одновременном выполнении.
- **`pickTarget`:** ближайший в радиусе; враг ровно на границе радиуса; никого в радиусе → нет цели.
- **`tickWaves`:** спавн с интервалом, пауза только после зачистки, победа после последней волны.

Компоненты, рендер и анимации не тестируем — их проверяет ручной прогон по критериям §7.
Прецедентов в репо пока нет: первые тесты появятся на 7.2.

## 9. Definition of Done

MVP закрыт, когда выполняется всё:

1. `npm run dev` — консоль чистая, ошибок three.js нет.
2. Волны идут, башни стреляют, экономика работает, анимации из §6 на месте.
3. Бездействие → поражение; разумная игра → победа; рестарт работает с обоих экранов.
4. `npm run build && vercel deploy --prod` — играется по ссылке в чужом браузере.
5. README со скриншотом + запись экрана 30–60 секунд.
   **Без пункта 5 проект в портфолио не считается положенным** — смотрят видео и ссылку,
   а не исходники.

На DoD — тег `v0.1.0` с release notes.

## 10. Бэклог после MVP

По одной системе за раз:

1. 2–3 типа врагов и башен с разными ролями (урон / замедление / площадь)
2. Режимы наведения: ближайший / первый / сильный, переключение кликом по башне
3. Скелетная анимация: анимированные модели (Quaternius), ходьба и эмоции персонажей
4. Богатые финальные сцены: персонажи радуются/грустят, конфетти, звук
5. Апгрейды башен
6. Звук: выстрелы, смерть врага, начало волны
7. Второй уровень + выбор уровня
8. Главное меню
9. Управление камерой: панорама и зум мышью в пределах карты
