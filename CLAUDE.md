# td3d

3D tower defense на Vite + React 19 + TypeScript + three.js + @react-three/fiber + drei + zustand.
Источник истины по MVP — [docs/SPEC.md](docs/SPEC.md).

## Процесс

- **Spec-driven.** Реализация строго по `docs/SPEC.md`. Отклонение — сначала правка спеки, потом код.
- **Каждый тикет или фича — в своей ветке** от `main`: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
  Прямых коммитов в `main` нет, даже для каркаса и настройки.
- **Вливание — только через pull request.** Мержит пользователь после ручной проверки. Агент не мержит никогда.
- Коммит, пуш и открытие PR — только после явного разрешения в чате на текущую задачу.
- Один тикет — одна сессия, без субагентов.

## Зависимости и безопасность

- Ставить только то, без чего задача не решается. Сначала проверить, нельзя ли обойтись тем, что уже есть.
- Перед установкой нового пакета: он активно поддерживается (свежие релизы, живой репозиторий),
  у него известный автор и заметная аудитория. Опечаточные имена и малоизвестные форки не ставим.
- Пакет, который ломает дерево зависимостей (конфликт peer-зависимостей, нужен `--force` или `--legacy-peer-deps`), не ставим.
- `package-lock.json` коммитится всегда.
- npm 11 блокирует install-скрипты пакетов. Разрешать их (`npm install-scripts approve`) только с объяснением зачем.
- Перед каждым PR: `npm audit` без уязвимостей уровня moderate и выше, `npm ls` без ошибок.

## Команды

- `npm run dev` — dev-сервер
- `npm run build` — проверка типов и сборка
- `npm run lint` — oxlint
- `npm audit` — проверка уязвимостей

## Технические правила

- Покадровое состояние (позиции врагов и т.п.) — в `useRef`, мутации внутри `useFrame`. Никогда в `useState`.
- В zustand — только то, что видит UI и что меняется редко: деньги, жизни, волна, список башен.
- Любое движение умножать на `delta` из `useFrame`.
- Ось Y смотрит вверх, земля лежит в плоскости XZ.
- Тесты (Vitest) — только для логики: стор, выбор цели, волны.
